# 连接比赛数据库（本机可视化工具）

> 目标库：`team12` @ RDS PostgreSQL 16.15（`pgm-2ze9t2uh39o1115k.rwlb.rds.aliyuncs.com:5432`）
> 网络前提：RDS 的 5432 **只对比赛 ECS 内网开放**，本机直连不通，必须经本队 ECS `101.201.239.22` 走 SSH 隧道。
> 适用：本机 Windows / macOS / Linux 上任何图形化客户端。

---

## 0. 先选路线

| 路线 | 做法 | 适合 |
|---|---|---|
| **A. 客户端内置 SSH 隧道**（推荐） | 在 DBeaver / pgAdmin / Navicat 里直接填 ECS 和 RDS 两段信息 | 日常开发，一次配好，不用额外进程 |
| **B. 外部隧道 + 本地端口** | 先跑 `scripts/db/pg_tunnel.py keepalive`，客户端连 `127.0.0.1:15432` | 客户端不支持 SSH（如 VS Code 插件），或想复用到多个工具 |

两条路线连的是同一个库，不影响看到的表。

---

## 1. 推荐工具：DBeaver Community

免费、对 PostgreSQL 支持最完整、自带 SSH 隧道，Windows/macOS/Linux 都有：<https://dbeaver.io/download/>

### 1.1 新建连接

连接 → 新建 → **PostgreSQL** → 下一步。

**Main（主标签）——填 RDS 信息：**

| 字段 | 值 |
|---|---|
| Host | `pgm-2ze9t2uh39o1115k.rwlb.rds.aliyuncs.com` |
| Port | `5432` |
| Database | `team12` |
| Username | `team12` |
| Password | 队内发的 `PGPASSWORD` |

**SSH（第二个标签）——填 ECS 信息，必须勾选 Use SSH Tunnel：**

| 字段 | 值 |
|---|---|
| Use SSH Tunnel | ✅ 勾选 |
| Host/IP | `101.201.239.22` |
| Port | `22` |
| User Name | `root` |
| Authentication Method | `Password` |
| Password | ECS 的 root 密码 |

> **最容易填错的地方**：Main 标签的 Host 要填 **RDS 内网地址**，不是 `127.0.0.1`。
> DBeaver 会先在 ECS 上建好隧道，再把 Main 里填的地址**发给 ECS 去解析**，所以这里必须写 ECS 视角能访问的地址。
> 填成 `127.0.0.1` 会变成"连 ECS 自己身上的 5432"，报 Connection refused。

### 1.2 让表名可以直接写（可选但强烈建议）

默认 `search_path` 是 `"$user", public`，而所有业务表在 `factopia` schema 里，所以不写前缀会报 `relation "job" does not exist`。

两种解法，任选：

- **驱动属性**：连接设置 → 驱动属性 → 新增
  - 名称 `options`，类型 `string`，值 `-c search_path=factopia,public`
- **或在 SQL 编辑器里**每次会话执行一次：`SET search_path = factopia, public;`（DBeaver 里可以存成 script，或用「初始化 SQL」）

顺带建议加一条 `options` 里的时区：`-c search_path=factopia,public -c TimeZone=UTC`。
RDS 服务器默认时区是 **Asia/Shanghai**，`timestamptz` 存的是绝对时刻不会错，但显示和导出的 CSV 会带 `+08:00`；团队约定按 UTC 就统一设成 UTC，避免比对时看花眼。

### 1.3 看到所有表

连上后，左侧 Database Navigator：

```
team12
└── Schemas
    ├── factopia      ← 业务表都在这里：54 张（51 逻辑表 + 3 个 daily_bar 分区子表）
    │   ├── Tables
    │   ├── Views       ← 4 个派生视图
    │   └── Indexes
    ├── public        ← vector 扩展在这里
    └── vector
```

看不到表时先确认：展开的是 `factopia` 而不是 `public`；以及工具栏的「显示空 schema / 显示系统对象」过滤是否把空表隐藏了（DBeaver 有 `Show empty folders` 之类的过滤器）。

## 2. 备选：pgAdmin 4 / Navicat / DataGrip

三者都支持 SSH 隧道，字段名不同、含义一致。

**pgAdmin 4**：Register → Server
- Connection 标签：Host = RDS 主机名，Port `5432`，Maintenance database `team12`，Username/Password = `team12`
- SSH Tunnel 标签：勾 Use SSH tunneling，Tunnel host `101.201.239.22`，Tunnel port `22`，Authentication `Password`，Username `root`，填 ECS 密码

**Navicat**：连接属性
- 常规标签：主机 = RDS 主机名，端口 `5432`，初始数据库 `team12`，用户名/密码 = `team12`
- SSH 标签：勾 Use SSH Tunnel，主机 `101.201.239.22`，端口 `22`，用户名 `root`，认证方式选密码

**DataGrip**：Data Source → PostgreSQL
- General 标签：Host/Port/Database/User/Password 同上
- SSH/SSL 标签：勾 Use SSH tunnel，Host `101.201.239.22`，Port `22`，Auth type `Password`，User `root`

**VS Code PostgreSQL 插件**：不支持 SSH 隧道，只能走路线 B。

## 3. 路线 B：外部隧道 + 本地端口

适合客户端不支持 SSH，或者想一条隧道给多个工具共用。

```bash
export FACTOPIA_SSH_PASSWORD='<ECS root 密码>'
python scripts/db/pg_tunnel.py keepalive --local-port 15432
# 输出：[tunnel] 本地转发已就绪 127.0.0.1:15432
```

然后客户端填 `127.0.0.1` / `15432` / `team12` / `team12` / 库 `team12`。DATABASE_URL 等价于：

```
postgresql://team12:<密码>@127.0.0.1:15432/team12?options=-c%20search_path%3Dfactopia%2Cpublic
```

隧道是前台进程，Ctrl-C 结束；关掉终端客户端就断。

## 4. 命令行最快的一次性检查

```bash
psql "host=127.0.0.1 port=15432 dbname=team12 user=team12 options=-c search_path=factopia,public" \
     -c '\dt factopia.*' -c 'select count(*) from factopia.job'
```

没有本地 psql 也没关系，用仓库里的脚本即可：

```bash
python scripts/db/pg_tunnel.py check      # 版本 / 扩展 / 连接数 / 容量
python scripts/db/smoke_test.py           # 7 项行为断言
```

## 5. 报错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `Connection refused` 到 `127.0.0.1:5432` | Main 标签填了 `127.0.0.1`，但没建隧道 | 用 SSH 标签，或改走路线 B 的 15432 |
| `Connection timed out` 到 RDS 主机名 | 直连 RDS，公网没开 | 必须经 ECS 隧道 |
| `password authentication failed for user "team12"` | 把 ECS 密码填进了数据库密码 | 两套密码分开填 |
| `FATAL: no pg_hba.conf entry for host ...` | 出口 IP 不在白名单 | 确认隧道落在**本队** ECS（`101.201.239.22`） |
| `SSH: Auth fail` / `Auth cancel` | ECS 密码错，或 sshd 关闭了密码登录 | 先用 `ssh root@101.201.239.22` 手验 |
| 左侧只有 `public`，没有表 | 没展开 `factopia` schema | 展开 schema 或调过滤开关 |
| `relation "job" does not exist` | 未设 `search_path` | 加驱动属性 `options=-c search_path=factopia,public` |
| 连上后一会就断 | 空闲被回收 / 网络抖动 | DBeaver 连接设置里开 Keep-Alive（如每 60s），或 SSH 隧道保持活动 |

## 6. 两条使用纪律

1. **连接数**：队内账号上限 30。DBeaver 一个编辑器窗口可能占用 1–2 条连接，开十几个标签页就可能把配额吃掉。批量操作前把多余编辑器关掉，并给客户端设 idle timeout。
2. **带宽**：ECS 公网只有 **3 Mbps**，大结果集非常慢。查大表务必 `LIMIT`，不要 `SELECT *`；现在库里还没有数据，等 `daily_bar` 回填后会立刻感受到差别。

---

## 7. 安全提醒

- ECS root 密码与 RDS 密码**不要写进仓库**（`.env` 也要 gitignore）。仓库里的 `scripts/db/pg_tunnel.py` 只从环境变量读密码，不含任何口令。
- 本地客户端保存密码时，至少启用主密码（DBeaver 支持），避免明文落在配置里。
- 需要给别人演示时，用只读账号或临时视图，不要把 `team12` 主账号密码贴到聊天记录。
