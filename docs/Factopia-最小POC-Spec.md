## 1. 概述

### 1.1 目的

用最小的工程量证明：**同一套因子（人工定义的或 AI 自动挖掘的），可以在香港、英国、法国三个市场上分别做可复现的验证，判断它能否跨市场迁移，再按模拟客户授权构建组合，并拆分出汇率贡献。**

### 1.2 范围

| 包含 | 不包含（后续阶段） |
|---|---|
| 三个市场的行情、汇率、交易日历标准化 | 多语言公告和文本信号（阶段 1） |
| 每个市场一套 Qlib 数据集 | 跨地区审批流、信号目录界面（阶段 2） |
| Alpha158 分市场评估和迁移性分类 | 协作平台集成（阶段 2） |
| RD-Agent 分市场自动挖掘因子 | 分市场衰减监控（阶段 3） |
| 统一验证关卡 | 时间点一致的基本面数据、授权数据源（阶段 3） |
| 授权约束下的三市场组合、多币种回测、归因 | 真实客户数据、真实交易 |
| 版本化规则包（最简版）、MLflow 留痕、中文 HTML 报告 | |
| **每个步骤都有 Web 界面展示，并可从界面触发运行**（第 2.9 节） | |

### 1.3 用户

- **量化研究员**：通过命令行运行流程、查看报告、评审候选因子。
- **评审人**（演示对象）：阅读 HTML 报告和 MLflow 记录。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 市场 | HK（港交所）、UK（伦交所）、FR（巴黎泛欧交易所） |
| IC / RankIC | 因子值与未来收益的相关系数 / 秩相关系数，按截面每日计算 |
| ICIR | IC 均值 ÷ IC 标准差 |
| 数据切分 | 训练集 2015-01-01 至 2021-12-31；验证集 2022-01-01 至 2023-12-31；测试集 2024-01-01 至数据截止日 |
| 候选因子 | RD-Agent 产出、尚未通过验证关卡的因子 |
| 入库因子 | 通过验证关卡并经人工确认的因子 |
| 基础币种 | 组合计价和报告的币种，由授权指定 |

| 前端框架 | React + Vite + Tailwind CSS | 19.3.0 / 8.3.2 / 4.3.3 | MIT | 与 nuke-ai-collaborator 前端技术栈一致，便于日后集成 | UI |

| K 线和资金曲线 | [TradingView Lightweight Charts](https://github.com/tradingview/lightweight-charts) | 5.2.1 | Apache-2.0 | 专业交易软件级别的 K 线和时间序列体验 | UI |

**第 1 天实测结论（2026-10-06）：**
- PyPI 上的 pyqlib 0.9.7 **没有 Linux ARM 安装包**，在 Apple 芯片的 Docker 中无法安装。改为从源码编译，固定到 RD-Agent 官方镜像使用的同一提交 `2fb9380`（Qlib 版本显示为 0.9.8.dev26），两边 Qlib 一致。
- Qlib 的实验记录依赖 MLflow 文件存储，MLflow 3.13 起默认关闭该方式，因此锁定 `mlflow<3.13`（实际解析为 3.12.0）；连带 pandas 解析为 2.3.3，避开了 pandas 3.x 的兼容风险。
- 已在容器（Linux ARM）中验证：Qlib、skfolio、MLflow 可正常导入；yfinance 可取得三个市场的股票、指数和汇率数据（`.L` 股票币种为 GBp，需除以 100）；exchange_calendars 的 XHKG / XLON / XPAR 日历正常。

**兼容性风险（第 1 周验证）：**
- pandas 3.x 是大版本升级，Qlib 0.9.7 和 pyfolio-reloaded 可能尚未适配；如有问题，锁定 pandas 2.x。
- cvxpy 1.9 要求 Python ≥ 3.11，pyqlib 0.9.7 只提供 3.8–3.12 的预编译包，因此全项目统一使用 Python 3.12（3.11 亦可；3.13 无法安装 pyqlib 预编译包）。
- RD-Agent 在 Docker 中运行自己的 Qlib 环境，需要确认它使用的 Qlib 版本能读取我们导出的数据集。

#### 1.5.2 自研部分（现成框架不支持）

| 中文 HTML 报告 | 报告结构由本项目定义；用 Jinja2 模板 + 图表 | 约 300 行 |

## 2. 功能需求

每条需求格式：编号 / 描述 / 验收条件。

### 2.1 数据层（DATA）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| DATA-01 | 股票池由 `configs/markets.yaml` 定义：HK = 恒指成分股，UK = 富时 100，FR = CAC 40（POC 用当前成分股） | 修改配置文件即可增删股票，不改代码 |
| DATA-02 | 从 yfinance 下载每只股票自 2015-01-01 起的日线（开高低收、成交量，已复权） | 下载失败的股票列入数据质量报告，不中断整个流程 |
| DATA-03 | UK 股票价格从便士（GBX）换算为英镑（GBP） | 抽查 3 只 UK 股票，价格与英镑报价一致 |
| DATA-04 | 下载汇率：HKD、GBP、EUR 两两之间以及到基础币种的日汇率 | 任意交易日都能取得到基础币种的汇率；缺失时用前一日数据并记录 |
| DATA-05 | 用 exchange_calendars（XHKG / XLON / XPAR）校验每个市场的交易日；剔除非交易日数据，标记缺失的交易日 | 数据质量报告中列出每个市场缺失的交易日数量 |
| DATA-06 | 时间戳统一存为 UTC，并保留交易所本地时间和时区 | 标准化表中两个字段都存在 |
| DATA-07 | 数据质量检查：缺失值、零成交量、单日涨跌幅超过 50%、价格为非正数 | 生成数据质量报告（每市场一节）；超过阈值的股票被标记并在后续步骤中排除 |
| DATA-08 | 把每个市场的数据导出为一套 Qlib 数据集（`qlib_data/{hk,uk,fr}/`），配置自定义区域参数：无涨跌停限制，按金额成交 | 三套数据集都能被 `qlib.init(provider_uri=...)` 加载，并能读取到任意一只股票的数据 |
| DATA-09 | 每次数据构建生成数据快照指纹（文件内容哈希）并记入 MLflow | 相同输入两次构建，指纹相同 |

### 2.2 因子评估（FAC）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| FAC-01 | 在每个市场上分别计算 Alpha158 全部因子 | 三个市场各得到一张因子表 |
| FAC-02 | 预测目标：未来 20 个交易日收益（按各市场自己的交易日历计算） | 目标值不使用当日之后的价格以外的任何信息；标签末尾 20 天为空 |
| FAC-03 | 对每个因子、每个市场、每个数据切分，计算 IC、RankIC、ICIR、RankIC 的 t 值、五分位组合收益、Top 组合换手率 | 结果写入因子评估表（见 4.2） |
| FAC-04 | 按 3.5 节规则对每个因子做迁移性分类（只使用验证集结果） | 每个因子恰好有一个分类标签 |
| FAC-05 | 输出三市场因子相关结构对比（同一因子集在三个市场的相关矩阵） | 报告中有三张相关矩阵热力图 |

### 2.3 自动因子挖掘（MINE）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| MINE-01 | 在 Linux + Docker 环境中运行 RD-Agent `fin_factor`，分别指向 HK、UK、FR 三套 Qlib 数据集 | 三个市场都至少完成 1 轮完整循环（提出 → 实现 → 回测 → 反馈） |
| MINE-02 | 三个市场使用相同的挖掘方向描述（由研究员在配置中填写，例如"量价短期反转"） | 运行记录中三个市场的挖掘方向一致 |
| MINE-03 | 挖掘只能使用训练集和验证集；测试集对 RD-Agent 不可见 | RD-Agent 的数据配置中截止日期 ≤ 2023-12-31 |
| MINE-04 | 每一次尝试（包括失败的）都记入 MLflow：假设文本、因子代码、回测指标、LLM 模型名、时间 | MLflow 中尝试记录数 = RD-Agent 日志中的尝试数 |
| MINE-05 | 运行结束后导出候选因子清单（见 4.3）；候选因子**不能**直接写入因子库 | 因子库只能通过 VAL 流程写入 |
| MINE-06 | 只向 LLM 发送因子代码和统计结果，不发送原始行情数据 | 抽查 LLM 请求日志，确认不含原始数据表 |

### 2.4 统一验证关卡（VAL）

所有候选因子（包括 Alpha158 中准备入库的因子）都要经过以下检查，阈值在 `configs/validation.yaml` 中配置。

| 编号 | 检查 | 默认规则 |
|---|---|---|
| VAL-01 | 显著性（多重检验校正） | 验证集 RankIC 的 t 值 > 3；报告中列出本轮总尝试次数 |
| VAL-02 | 去冗余 | 与已入库因子的相关性 > 0.7 时，只保留 ICIR 较高的一个 |
| VAL-03 | 中性化 | 对规模、20 日动量、20 日波动率做截面回归中性化后，RankIC 方向不变 |
| VAL-04 | 成本后有效 | 扣除各市场成本和税费后，Top 五分位组合相对等权基准的年化超额收益 > 0 |
| VAL-05 | 迁移性分类 | 按 3.5 节规则打标签 |
| VAL-06 | 人工确认 | 通过 VAL-01 至 VAL-04 的因子，由研究员填写经济逻辑说明后，执行 `factopia approve <factor_id>` 才写入因子库 |

验收条件：每个候选因子都有一条验证记录，写明各项检查的结果；只有执行过 VAL-06 的因子出现在因子库中。

### 2.5 组合层（PORT）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| PORT-01 | 读取模拟授权 YAML（格式见全局设计 3.7），校验必填字段 | 缺少字段时报错并指出字段名 |
| PORT-02 | 把授权条款和规则包转换为 skfolio `MeanRisk` 约束：跟踪误差、不允许卖空、受限证券、市场上限、换手上限、交易成本 | 每个约束都能追溯到授权条款或规则编号 |
| PORT-03 | 信号来源：入库因子的等权合成得分（每个市场内部先做截面标准化） | 报告中列出使用的因子和权重 |
| PORT-04 | 月度调仓（每月最后一个交易日），只做多，用历史 252 日协方差 | 回测期内每次调仓都有权重记录 |
| PORT-05 | 复合基准：^HSI、^FTSE、^FCHI 按授权权重合成，换算为基础币种 | 基准收益序列可单独导出 |
| PORT-06 | 多币种回测：每日计算本地币种收益和基础币种收益；扣除各市场成本和税费（从规则包读取） | 回测结果包含本地收益、汇率收益、基础币种收益三列 |
| PORT-07 | 汇率拆分：基础币种收益 =（1 + 本地收益）×（1 + 汇率收益）− 1 | 三者恒等关系的误差 < 1e-10 |
| PORT-08 | Brinson 归因：按市场拆分配置效应、选股效应、汇率贡献 | 各项之和等于组合相对基准的超额收益（误差 < 1bp） |
| PORT-09 | 输出业绩指标：年化收益、波动率、夏普、最大回撤、跟踪误差、信息比率、平均换手 | 报告中按"全组合 + 每个市场"列出 |

### 2.6 规则包（RULE）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| RULE-01 | 规则包为 YAML 文件，文件名即版本号；每条规则包含：编号、市场、严重程度（block / warn / info）、描述、来源、负责人、生效日期、最后复核日期、状态 | 加载时校验格式 |
| RULE-02 | 组合生成后执行预检：受限证券、卖空、市场集中度、单只股票上限 | 每条命中记录规则编号和版本 |
| RULE-03 | 命中 block 级规则时，流程停止并输出原因；warn 和 info 级规则写入报告 | 构造一个违反卖空规则的授权，流程会停止 |
| RULE-04 | 成本和税费参数存放在规则包中，状态标记为"待合规确认" | 代码中没有写死的税率 |
| RULE-05 | 每个市场至少配置一条 info 级规则（对应业务 spec "每个地区至少触发一项规则提示"） | 演示报告中三个市场都有规则提示 |

### 2.7 实验追踪与复现（TRACK）

| 编号 | 描述 | 验收条件 |
|---|---|---|
| TRACK-01 | 每次运行记入 MLflow：Git 提交号、配置文件内容、数据快照指纹、规则包版本、随机种子、Python 依赖版本 | MLflow 界面中可以查看全部字段 |
| TRACK-02 | `factopia reproduce <run_id>` 根据记录重新运行（不含 RD-Agent 挖掘），结果与原运行一致 | 关键指标完全相同 |

## 3. 业务规则

### 3.1 各市场参数

| 参数 | HK | UK | FR |
|---|---|---|---|
| Yahoo 代码后缀 | `.HK` | `.L` | `.PA` |
| 交易日历 | XHKG | XLON | XPAR |
| 本地币种 | HKD | GBP（价格源为 GBX，需除以 100） | EUR |
| 基准 | ^HSI | ^FTSE | ^FCHI |
| 成本和税费 | 从规则包读取 | 从规则包读取 | 从规则包读取 |

### 3.2 成本和税费示例值（待合规确认）

| 市场 | 项目 | 示例值 |
|---|---|---|
| HK | 印花税 | 买卖双方各 0.1% |
| UK | 印花税 | 买入 0.5% |
| FR | 金融交易税 | 大市值股票买入 0.4% |
| 全部 | 佣金加冲击成本 | 单边 0.1%（POC 简化假设） |

### 3.3 跨市场日期对齐

- 因子评估：每个市场只使用自己的交易日。
- 组合回测：使用三个市场交易日的并集；某个市场休市时，该市场持仓价格沿用前一交易日，汇率照常更新。
- 调仓日：每月最后一个日历日之前，三个市场都开市的最后一天。

### 3.4 迁移性分类

基于验证集，记 HK、UK、FR 三个市场的 RankIC t 值为 t_HK、t_UK、t_FR，门槛 T = 3：

| 分类 | 判定 |
|---|---|
| 三市场通用 | 三个市场 RankIC 符号相同，且 \|t\| 都 > T |
| 地区特定 | 一个或两个市场 \|t\| > T；标签注明适用的市场 |
| 需调参 | 三个市场符号相同，但有市场 \|t\| ≤ T，且该市场 \|t\| > T/2 |
| 扣成本后无效 | 成本前满足以上任一分类，但未通过 VAL-04 |
| 无效 | 不满足以上任何一条 |

## 9. 因子挖掘方法全景与升级路线

> 本章记录因子挖掘领域的主要方法、代表性开源项目及其对本平台的适用性，作为后续选型和升级的依据。
> 开源项目数据（Stars、最近更新、许可证）查询于 2026-10-07，升级前应重新核对。

### 9.1 术语

| 术语 | 含义 |
|---|---|
| 因子 | 给股票打分的规则，用于判断哪些股票未来可能表现更好 |
| 因子挖掘 | 寻找新的、有效的因子：提出假设 → 写成可计算的公式或代码 → 用历史数据检验 → 根据结果改进 |
| 因子假设 | 挖掘的起点，例如"过去 20 天涨得多的股票会继续上涨" |
| 显式因子 | 能写成公式或代码、可以单独计算和解释的因子 |
| 隐式因子 | 神经网络内部学到的特征，无法写成公式，难以解释 |

### 9.2 六类方法

#### ① 人工设计与现成因子库

不做挖掘，直接使用已经总结好的因子。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| Qlib Alpha158 / Alpha360 | 158 / 360 个常用量价因子 | 4.9 万（Qlib） | MIT |
| WorldQuant Alpha101 实现（yli188/WorldQuant_alpha101_code） | 101 个公开公式因子 | 877 | 未声明 |
| 学术因子（Fama-French 等） | 市值、价值、动量、盈利能力等 | — | 公开数据 |
| 团队专有因子库 | 业务 spec 所述二十年积累 | — | 内部 |

#### ② 遗传规划与符号回归

随机生成公式，按"适者生存"逐代筛选、交叉、变异，保留历史表现最好的公式。不需要金融知识。在大模型出现之前是自动挖掘因子的主流方法。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| gplearn | Python 遗传规划库，量化领域最常用 | 1.9k | BSD-3 |
| DEAP | 通用进化计算框架 | 6.4k | LGPL-3.0 |
| PySR | 符号回归 | 3.8k | Apache-2.0 |

- 优点：速度快、成本低、无需 GPU 或 LLM。
- 缺点：产出的公式难以解释；尝试数量巨大，容易挖到只在历史数据上有效的假规律。

#### ③ 强化学习生成公式

训练一个"生成器"产生公式，以检验结果作为奖励，逐步学会生成更好的公式；可生成一组互补的因子。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| alphagen（ICT-FinD-Lab/alphagen） | 强化学习生成公式因子组合 | 1.3k | 未声明 |
| AlphaForge（DulyHao/AlphaForge） | AAAI 2025，生成与动态组合 | 432 | 未声明 |
| alpha-gfn（nshen7/alpha-gfn） | GFlowNet 生成多样化因子 | 124 | 未声明 |
| Alpha²（x35f/alpha2） | 搜索树方法 | 241 | 未声明 |

- 优点：学术前沿，效果通常优于遗传规划。
- 缺点：结果仍为难以解释的公式；以上项目均未声明许可证，不能直接用于公司项目；多数基于 A 股数据。

#### ④ 深度学习（隐式因子）

不产出公式，把原始价格数据直接输入神经网络，由网络学习有用的特征并输出预测。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| Qlib 模型库 | LSTM、GRU、Transformer、TRA、HIST、DoubleEnsemble 等 | 4.9 万（Qlib） | MIT |
| FactorVAE 等学术模型 | 把因子作为网络内部结构学习 | 开源实现零散 | — |

- 优点：能捕捉复杂的非线性关系，预测效果有时最好。
- 缺点：可解释性最差；需要更多数据和算力（可能需要 GPU）。

#### ⑤ 大模型 Agent（AI 研究员）

由大语言模型提出假设、编写因子代码、读取回测结果并迭代改进。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| RD-Agent（microsoft/RD-Agent） | 最成熟的开源实现，基于 Qlib | 1.5 万 | MIT |
| AlphaAgent（RndmVariableQ/AlphaAgent） | 增加防止重复假设的机制；只支持 A 股（Tushare） | 418 | 未声明 |
| Alpha-GPT、QuantAgent 等 | 学术论文，多数未完整开源 | — | — |

- 优点：每个因子附带假设说明，可解释、便于审批；可扩展到文本数据；速度快。
- 缺点：有 LLM 调用费用；假设多基于已知理论，较少凭空发现新规律；同样存在挖到假规律的风险，必须经过验证关卡。

#### ⑥ 文本与另类数据因子

从新闻、公司公告、财报电话会议记录等文字中提取信号，例如统计风险相关措辞的变化，或由大模型判断管理层语气。

| 项目 | 内容 | Stars | 许可证 |
|---|---|---|---|
| FinBERT（ProsusAI/finBERT） | 金融文本情绪模型（英文），2022 年后未更新 | 2.2k | Apache-2.0 |
| FinGPT（AI4Finance-Foundation/FinGPT） | 金融大模型项目，含情绪分析 | 2.1 万 | MIT |

### 9.4 架构约束

为便于替换和升级，所有挖掘方法遵循以下约束（与第 2.3、2.4 节一致）：

1. **挖掘引擎可替换**：每种方法实现统一接口，输入为"市场数据集、挖掘方向、数据截止日期"，输出为统一格式的候选因子清单（第 4.3 节）。
2. **统一验证关卡**：任何方法产出的因子都必须通过第 2.4 节的验证关卡，并在三个市场分别检验后，经人工确认才能入库。
3. **数据隔离**：挖掘过程只能使用截止 2023-12-31 的数据（第 2.3 节 MINE-03）。
4. **全程留痕**：每次尝试（包括失败的）都记录假设、代码、指标和所用模型。

### 9.5 升级路线

| 顺序 | 升级内容 | 价值 | 前提 |
|---|---|---|---|
| 1 | **文本因子（⑥）**：采集三个市场的公告，用大模型提取"风险表述变化"信号 | 实现业务 spec 演示主线 | 确认公告数据来源和许可（港交所披露易、英国 RNS、法国 AMF） |
| 2 | **RD-Agent 场景描述本地化**：把提示词中的"CSI300"等 A 股描述替换为对应市场 | 提高 AI 提出假设的针对性 | 继承扩展方式实现，不修改 RD-Agent 源码 |
| 3 | **⑤ + ⑥ 结合**：扩展 RD-Agent 的数据来源，使其能基于公告文本提出假设 | "AI 自动挖掘 + 多语言文本信号"两个卖点合一，形成差异化 | 完成第 1、2 项 |
| 4 | **遗传规划对照（②）**：接入 gplearn，与 RD-Agent 在相同数据上对比 | 回答"为什么使用 AI"，并作为备用引擎 | 统一挖掘接口完成 |
| 5 | **深度学习模型（④）**：在组合层试用 Qlib 模型库做非线性信号组合 | 对应业务 spec "信号智能" | 验证关卡和组合层稳定；评估可解释性要求 |
| — | 强化学习方法（③） | — | 暂不采用；若相关项目补充可商用许可证，再重新评估 |

### 9.6 重新评估的触发条件

出现以下情况时，应回到本章重新评估选型：

- RD-Agent 停止维护，或新版本的接口变化导致第 7.4 节（全局设计）的适配失效；
- 第 ③ 类项目补充了可商用的许可证；
- 出现新的、成熟度明显更高的大模型 Agent 开源项目；
- 团队专有因子库开放接入；
- 业务方要求取消或放宽"可解释"要求。
