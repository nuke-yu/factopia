Factopia 跨境量化研究平台架构

同一个投资假设，在香港、伦敦、巴黎三个市场分别检验，判断能否跨市场迁移，再按客户授权构建组合，经规则检查和跨地区审批后上线监控。本页用五张图说明平台的分层、流程、组件协作、部署和数据流向，供开发时对照。

图 1总体架构：八层与横切能力

自下而上，数据层是一切的基础，界面层只读取各层的产出、不做计算。右侧四项横切能力被所有层共用。

图 2业务流程：从研究假设到分市场监控

十个环节对应业务 spec 的端到端工作流。机器负责检验和发现问题，带“人工”标记的环节由人判断。监控发现某一市场衰减时，只停用该市场的版本，并把结果反馈给因子生产。

角色工作台

十个环节按角色归入五个工作台。AI 助理在工作台中完成工作，每一步的提示词、数据、产出和费用都在页面上可见；真人在同一页面审核和决策。原“交易员”角色改为组合经理助理，只出方案、不下单。

图 3一轮 AI 挖掘：RD-Agent 想与写，Qlib 算与评

RD-Agent 负责提出假设、编写因子代码和总结；判断因子好坏由 Qlib 回测完成。每轮一个想法，结果决定新因子是否进入“最佳组合”，并引出下一轮假设。

图 4运行部署：全部在 Docker 中，只用容器内路径

RD-Agent 启动的回测容器交给 compose 内的独立 Docker 引擎（dind），而不是宿主机的 Docker。dind 与 rdagent 以相同路径挂载同一批命名卷，因此配置中不出现任何宿主机路径，Mac、Windows 和云服务器使用同一套配置。

附 2开发约定

  1. 只用容器内路径。配置和代码中不出现宿主机绝对路径；数据放在命名卷 /workspace/runtime。
  2. 不改 RD-Agent 和 Qlib 源码。依次用配置、模板覆盖、继承扩展解决；确需 fork 时单独记录原因。
  3. 市场相关设置放在配置里。股票池、基准、成本、持股比例、预测周期都在 configs/ 中，不写死在代码里。
  4. 2024 年以后的数据对 AI 不可见。挖掘只用截至 2023-12-31 的数据集；测试集只在最终报告中使用一次。
  5. AI 产出只是候选。任何来源的因子都要通过统一验证关卡、三市场分别检验和人工确认，才能入库。
  6. 每次运行都要可复现。记录代码版本、数据指纹、规则包版本、预测周期和随机种子；依赖由 uv.lock 和 Dockerfile 锁定。
  7. 只用可商用许可证的组件。未声明许可证的开源项目不引入。
  8. 先测试，通过后再提交。提交说明只描述改动本身；API 密钥只放在本地 .env。
  9. Windows 同事在 WSL2 中开发，代码放在 WSL2 文件系统内；仓库强制使用 LF 换行。
